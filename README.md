# 🏛️ مدللني mdllni — منصة خدمات الناصرية

منصة حقيقية متكاملة (ليست وهمية) تربط الزبائن بمقدمي الخدمات في الناصرية / ذي قار.
الإصدار الحالي: **v9.0** — رموز OTP تصدر وتُتحقق من **Supabase Auth نفسها** (بلا أي مزود بريد خارجي) · تحقق بخطوتين إجباري · جهاز واحد = حساب واحد · ربط بريد إجباري للحسابات القديمة · ذمة ذرية بالقاعدة · 241+ حالة احتيال موثقة ومعالَجة.

## 🧱 البنية
- **الواجهة:** `index.html` + `css/style.css` + `js/app.js` (منطق التطبيق) + `js/cloud.js` (طبقة السحابة) + `js/cloud-patch.js` (رقعة الهوية) — HTML/CSS/JS مباشر بدون خطوة بناء.
- **الخادم:** دوال Vercel Serverless داخل `api/` (`_engine` قواعد العمل · `auth` الهوية · `data` البوابة · `_lib` الأدوات · `health` الفحص).
- **القاعدة:** Supabase (PostgreSQL) — 19 جدولاً حقيقياً + RLS كامل (الوصول فقط عبر service_role من الخادم) — **+ Supabase Auth كمُصدِر لرموز OTP**.
- **وضع مزدوج:** بدون متغيرات Supabase تشتغل المنصة بوضع عرض محلي (localStorage) — للتجربة فقط.

## 🚀 التشغيل خطوة بخطوة

### 1) Supabase — القاعدة
1. أنشئ مشروعاً على https://supabase.com (اختر Region قريب).
2. **SQL Editor** → الصق كل محتوى `supabase/schema.sql` → **Run** — تنزرع الجداول الـ19 + التصنيفات والخدمات + الإعدادات + دالة الذمة الذرية (يشمل ترقيات v7→v12).
3. من **Project Settings → API** انسخ `Project URL` و`service_role`.

### 2) Supabase — تفعيل رموز OTP (خطوتان، نفس اللي بالصورة)
1. **Authentication → Sign In / Providers → Email** → فعّله (ON) → Save.
2. **Authentication → Emails → قالب «Magic Link»** → استبدل المحتوى بالقالب الجاهز (يعرض الرمز بوضوح) → Save:

```html
<h2>رمز التحقق — مدللني</h2>
<p>رمز الدخول / التفعيل مالتك:</p>
<p style="font-size:34px;font-weight:bold;letter-spacing:10px;direction:ltr;text-align:center">{{ .Token }}</p>
<p>الرمز صالح لساعة ويُستخدم مرة واحدة. إذا ما طلبته أنت، تجاهل الرسالة بأمان.</p>
```

> ملاحظة صدق: الإرسال المدمج بسوبابيس محدود (مصمم للبدايات والتجربة). يكفي المرحلة الحالية؛ وأول ما يكثر المستخدمون: **Authentication → SMTP Settings** وحطّ أي SMTP (مثلاً Gmail App Password — دقيقتان) بلا أي تغيير كود.
> صفحة URL Configuration (Site URL) ما تخصنا — القالب مالنا كود فقط بلا روابط.

### 3) Vercel
1. ارفع المجلد لـ GitHub ثم Import في Vercel (Framework Preset = **Other**).
2. **Settings → Environment Variables** حسب `.env.example`: `SUPABASE_URL` · `SUPABASE_SERVICE_ROLE_KEY` · `JWT_SECRET` · `ADMIN_PHONE` · `ADMIN_PASSWORD` · `ADMIN_NAME`. (لا MAIL_* إطلاقاً — انتهت الحاجة لها بـ v9.0)
3. Deploy → تحقق: `/api/health` يرجّع `"version":"v9"` و`otpReady:true`.

### 4) دخول الإدارة
حساب الإدارة يُنشأ تلقائياً من `ADMIN_PHONE`/`ADMIN_PASSWORD`. إذا كان بريد الإدارة مفعّلاً بالقاعدة فالدخول يتطلب رمز Supabase لبريده — فعّل Email provider أولاً. راقب الأجهزة والطلبات من تبويب **🛡️ الأمان**.

## 🔐 الأمان (إصدار الهوية v8/v9)
- **OTP بالبريد إجباري:** 6 أرقام يولّدها ويرسلها **Supabase Auth** ويتحقق منها (أحادية الاستخدام، صلاحية ساعة) — للتسجيل والدخول والجهاز الجديد وربط البريد. حساب بريده غير مفعّل لا يدخل بلا رمز أبداً. ونضيف فوقها: كولداون دقيقة + حد 8 رموز يومياً (قواعدنا).
- **جهاز واحد = حساب واحد:** فهرس فريد بالقاعدة؛ الحساب الثاني من نفس الجهاز يُرفض (`device_in_use`)؛ بصمة الجهاز + آخر IP موثّقان لكل حساب.
- **تبديل التلفون العطلان:** جهاز جديد → رمز بريد → «معلق» → الإدارة تعتمد من تبويب الأمان (تبديل يلغي القديم).
- **إلغاء جهاز يقتل جلسته فوراً** (401 `device_revoked`).
- **الحسابات القديمة بلا بريد:** تدخل ثم يظهر مودال ربط البريد بكل دخول حتى يتم (إجباري عملياً) — والربط المتقاطع (بريد محجوز لرقم آخر) ممنوع.
- **شبكة التواطؤ:** تطابق جهاز أو آخر IP بين زبون ومقدم مطابق → استبعاد + تعليم 🚨 + حدث أمني موثّق.
- **الذمة الذرية:** `ur_apply_debt` RPC بمعاملة واحدة — سباق الإكمال المزدوج يقيّد عمولة واحدة فقط (مُختبَر).
- الباسوردات scrypt · الجلسات JWT (HS256) مربوطة ببصمة الجهاز · Turnstile اختياري (بزوج المفاتيح كاملاً فقط).

## 🔌 الـ API
| المسار | الوظيفة |
|------|--------|
| `GET /api/health` | الوضع + الإعدادات العامة (`turnstileSiteKey`, `otpReady`) |
| `POST /api/auth` | `register` / `login` / `verifyOtp` / `resendOtp` / `bindEmail` / `me` |
| `POST /api/data` | `snapshot` + كل العمليات (قبول، تسعير، توثيق، أجهزة، تسوية…) |
