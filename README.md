# مدللني mdllni — منصة خدمات الناصرية

الإصدار **v10**: هوية متكيفة، OTP بريد من **Supabase Auth فقط**، وأجهزة موثوقة بدون حظر دائم مزعج.

## الهوية والأمان
- كلمة المرور هي الخطوة الأولى، ورمز البريد من Supabase هو الخطوة الثانية عند التسجيل، الجهاز الجديد، انتهاء الثقة، أو الاستعادة.
- الجهاز الموثوق يبقى 30 يوماً (7 أيام للإدارة). الحد 3 أجهزة؛ الرابع يستبدل أقدم جهاز غير مستخدم ويبلغ صاحب الحساب.
- الجهاز المشترك مسموح للعائلة، لكنه يبقى إشارة خطر تمنع/تراجع التعامل الذاتي بين الزبون ومقدم الخدمة.
- IP وحده لا يسبب حظراً دائماً. الفشل المتكرر يسبب تبريداً متدرجاً: دقيقة، ثم 15 دقيقة، ثم ساعة.
- إلغاء جهاز يقتل جلساته فوراً. المستخدم والإدارة يقدران على الإلغاء.
- استعادة كلمة المرور لا تتم إلا بعد نجاح `/auth/v1/verify` من Supabase؛ لا يوجد reset مباشر أو رابط يثق بإيميل قادم من العميل.
- لا يوجد `_mail.js`، ولا `MAIL_*`، ولا رمز محلي، ولا دخول بديل إذا تعذر إرسال البريد.

## الإعداد
1. شغّل migration v13 للقاعدة الحالية.
2. ضع متغيرات `.env.example` في Vercel. الأسرار تبقى في السيرفر فقط.
3. في Supabase فعّل Email واستخدم `{{ .Token }}` في قالب Magic Link ليصل كود 6 أرقام.
4. ضع رابط الإنتاج في Authentication → URL Configuration.
5. شغّل `npm test` ثم انشر.

## ملاحظات تشغيلية
- الخادم يستخدم `fetch` الأصلي في Node للوصول إلى Supabase REST؛ لا توجد حزم تثبيت أو SDK بريد خارجي.
- البريد المدمج في Supabase مناسب للبداية لكنه best-effort وله حدود إرسال. المنصة لا تتجاوز OTP عند rate limit.
- جداول التطبيق لا تُقرأ من المتصفح؛ RLS مفعّل والوصول يتم عبر دوال Vercel باستخدام service role.
- أرقام الطلبات الجديدة تبدأ بـ `MD-`.
